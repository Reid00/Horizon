### [Rust 1.100 稳定 never 类型与自定义分配器](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100 已发布，稳定了长期等待的 never 类型和自定义分配器，面向使用这些语言特性的 Rust 开发者。Cargo 同时引入依赖冷却配置（RFC 3923）：启用后解析器会忽略发布时间晚于设定阈值的版本，除非该版本已记录在 Cargo.lock 中；cargo install 默认使用 .crate 包内的现有 lockfile，--locked 因此成为 no-op。Cargo 还会默认以 warn 级别报告未使用依赖。

hackernews · mbStavola · 11月12日 18:39 · [社区讨论](https://news.ycombinator.com/item?id=50472038)

**「背景」** 自定义分配器在 Rust 中讨论已久：RFC 1398 提出了按类型指定分配器的设计，而替换全局默认分配器的能力此前只在 nightly 上提供，相关跟踪 issue 也明确该改动不增加稳定 API。1.100 稳定了 allocator\_api 的核心部分并引入 Allocator trait，使库作者可以为 Vec 和 Box 等标准库类型定义并使用自定义分配器。

**「影响」** Cargo 的依赖冷却默认最小发布年龄为 0，因此仅升级到 Rust 1.100 不会自动改善供应链防护；团队需要在 Cargo 配置中显式设置 min-publish-age（例如 14 天）才会生效，而已经记录在 Cargo.lock 中的版本在后续解析时仍会被沿用。

**「社区讨论」** 社区评论普遍欢迎此次发布，并补充了博客未列出的稳定 API，如 bool::toggle\(\)、Box::map\(\) 以及 str::trim\_prefix\(\)/trim\_suffix\(\) 和 Path::trim\_prefix\(\)。也有用户质疑编译器是否变快，并抱怨每天需要 cargo clean 清理约 90GB 临时文件。

### [PostgreSQL 22 年前类型混淆原语被串成 RCE 利用链](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 8.0/10

安全研究者公开了一套利用链，称可将 PostgreSQL 中一个存在约 22 年的类型混淆原语用于远程代码执行，漏洞编号为 CVE-2026-6460。文章重点讨论数据库内部机制和严重性定级，但现有材料未给出受影响版本、利用前置条件或修复状态。因此，目前能确认的是作者披露的利用思路，尚不能判断实际影响范围。

hackernews · ozirus · 11月12日 18:22 · [社区讨论](https://news.ycombinator.com/item?id=50471761)

**「背景」** CVE-2026-6460 是 PostgreSQL 的一个类型混淆漏洞，CVSS 评分为 8.8。OpenCVE 的描述称，拥有对象创建权限的攻击者可通过 ALTER ... SET DATA TYPE 等操作，以运行数据库服务的操作系统用户身份执行任意代码。该漏洞并非新引入的单一缺陷，而是把 PostgreSQL 内部长期存在的类型表示问题（即标题所说的 22 年历史原语）逐步组合成可利用链，因此其实际门槛需要结合攻击者已有权限来理解。

**「实际影响与定性争议」** 这条利用链的前提是先拥有一个数据库账号，因此实际暴露面集中在多租户或共享实例：低权限数据库用户可能借此在数据库主机上执行代码，运营方应把数据库凭据视为接近主机级的信任边界，并限制不受信任方获得账号。评论区多位读者（如 logophobia、jmuguy）认为，把它称为 RCE 会高估风险，更准确的定性是提权，因为攻击者需要已认证的数据库访问；这一判断属于社区意见，而非来源确认的结论。

**「社区讨论」** 评论中，logophobia 和 jmuguy 认为相关利用需要已认证的数据库访问，称其为 RCE 会夸大危险性，更应归类为权限提升，主要影响多租户数据库；igbanam 和 sailfast 则称赞文章对漏洞发现过程和数据库内部机制的讲解。
